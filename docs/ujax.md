# UJAX — 권한과 외부 연동의 실패 처리

[프로필로 돌아가기](../README.md) · [팀 프로젝트](https://github.com/ujax-v2/UJAX)

## 내가 담당한 범위

워크스페이스·멤버 API와 가입 신청·승인·취소, 역할별 권한을 구현했습니다. 커뮤니티에서는 탈퇴·삭제된 멤버의 게시글과 댓글 조회 문제를 다뤘습니다. 이메일 인증과 Mail Outbox, Mattermost 알림, S3 Presigned URL 기반 이미지 연동도 담당했습니다.

Judge0 채점, 백준 제출 Extension, 인증 기반과 인프라 구축 등은 팀원별 담당 영역입니다. [팀별 기여](https://github.com/ujax-v2/UJAX#team-contributions)에서 전체 역할을 확인할 수 있습니다.

## 메일 전송과 비즈니스 처리 분리

메일 전송은 외부 SMTP 상태에 영향을 받습니다. 회원가입·초대 요청 처리와 실제 메일 도착 시점을 분리하고, 실패한 전송 요청을 다시 처리할 수 있도록 DB Outbox를 도입했습니다.

1. 메일 요청을 `mail_outbox`에 저장합니다.
2. 스케줄러가 처리할 요청을 가져옵니다.
3. 메일 타입에 맞는 템플릿으로 전송합니다.
4. 실패하면 상태와 재시도 흐름에 따라 후속 처리를 진행합니다.

회원가입은 대기 정보를 먼저 저장하고 이메일 인증 완료 시 실제 계정을 생성하도록 변경했습니다. 동일 이메일의 재요청은 기존 가입 대기 정보를 재사용하며 코드와 만료 시간을 갱신하고, 만료된 대기 정보는 정리 배치로 처리했습니다.

[설계·구현·테스트 근거 — PR #85](https://github.com/ujax-v2/ujax-server/pull/85)

## 검증과 설계 범위

Outbox 서비스, SMTP 전송, 템플릿, 스케줄러와 가입 대기 정리 배치의 테스트를 작성했습니다. API 요청 성공과 실제 메일 발송 성공을 구분해 설명하고, 프론트엔드에서 변경된 이메일 인증 순서를 따르도록 연동 계약을 명시했습니다.

PR #85 시점에는 멀티 인스턴스 워커의 행 선점 동시성 보강과 재전송·인증 시도 횟수 제한을 후속 과제로 남겼습니다. 이 문서는 당시 변경 범위를 설명하며, 중복 발송의 완전 방지나 멀티 인스턴스 안전성을 검증했다는 의미는 아닙니다.

## 외부 알림의 책임 분리와 추적

알림 서비스에 모여 있던 예약·수정·취소와 실제 전송 책임을 나눴습니다. 스케줄러를 인프라 계층으로 이동하고, 알림 전송 이력 테이블 의존을 구조화 로그와 마지막 오류 정보로 정리했습니다.

관련 테스트와 함께 실제 Mattermost 웹훅으로 예약 알림을 보내고, `PROCESSING_STARTED`·`DELIVERED` 로그와 발송 후 데이터 처리를 확인했습니다.

[구조 변경과 실제 전송 검증 — PR #97](https://github.com/ujax-v2/ujax-server/pull/97)

## 이 작업에서 배운 점

비동기로 분리하면 요청은 먼저 끝낼 수 있지만, 실패·재시도·처리 중단을 별도로 다뤄야 합니다. 메일과 알림 작업에서는 전송 코드뿐 아니라 상태 관리, 복구 흐름, 로그까지 함께 설계하는 경험을 쌓았습니다.
